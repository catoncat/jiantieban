# ADR-0001：密钥以 jt 为唯一来源，App 是 jt 的原生界面

- 状态：已接受
- 取代：早期设计中“密钥记录 = 被标记为密钥的剪贴板记录”和“取消密钥后解密回普通记录”

## 背景

早期设计把密钥当作剪贴板记录的一个属性：标记后记录带上 `is_secret`，`:secret` 视图就是 `items WHERE is_secret = 1`。

用户的密钥大多不是经剪贴板进来的，而是直接 `jt add` 或从其他工具迁进 jt。按旧定义，App 的密钥视图只看得到剪贴板里标记过的少数几条，其余全都看不到。旧视图本身也在丢东西：

- 标记过的记录照样按保留策略被清理。
- 删除密钥行有意只删本地、不动 jt（引用可能已贴到别处在用），删掉后 jt 里那条在 App 里再也看不到。
- 在终端用 `jt mv` 改名后，本地名称与 jt 不一致。

实际上代码已经默认“jt 负责长期保存，剪贴板记录只是临时指针”，只是视图和文档还停在旧定义上。

## 决策

1. **密钥记录 = jt 里的一条记录。** 真值、名称、遮罩、命名空间都以 jt 为准；本地名称只是展示缓存。
2. **App 的密钥视图是 jt 的原生界面。** 列出 jt 的全部记录（按命名空间分组），查看、贴引用、贴明文、改名、删除都落到 jt。
3. **剪贴板历史只是入口。** 标记为密钥 = 把真值交给 jt 新建一条记录，原剪贴板记录变成只存引用的引用记录；引用记录按普通保留策略处理，删除或过期不影响 jt。
4. **没有“取消密钥 / 恢复明文”。** 要用明文有贴明文和查看；不再需要就删除。标错由标记后的短时撤销兜底。
5. **在密钥视图里删除 = `jt rm`**，需要再按一次确认。
6. **App 不触发 `jt sync`。** 同步由用户在终端执行；App 只提示有未同步的改动。

## 后果

- App 自己不做保险库，但它是 jt 的原生界面；仍不做密码管理器能力（自动填充、浏览器扩展、TOTP、团队共享）。
- 依赖 jt 提供机器可读的列表（`jt ls --json`）和状态（`jt status --json`）。
- 取消密钥入口全部移除；`Store.unmarkSecret` 的写回与去重合并只作为标记撤销的实现保留。
- jiantieban CLI 里与 jt 重复的密钥命令收敛到 jt，旧命令只打印去向。
- 普通剪贴板路径不受影响：只在进入密钥视图、标记、贴密钥、改名、删除，以及发现 vault 文件变化时调用 jt。
